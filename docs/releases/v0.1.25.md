## Security

gitdr is now built with Go 1.26.11, which fixes GO-2026-6859 in `net/http`, a race in `MaxBytesReader` that can crash an HTTP/1 server. gitdr runs no HTTP server, but govulncheck finds a path to the affected functions through the HTTP client the sources use, so the binary is rebuilt rather than left to be flagged. v0.1.24 was built with Go 1.26.10.

`golang.org/x/crypto` moves to v0.59.0, which fixes GO-2026-5932. govulncheck finds no call to the affected code. It is updated anyway, so a scanner that reads the module list inside the binary has nothing to flag.

## Dependencies

The GitLab client moves from v3.29 to v3.48. gitdr's own code does not change, and the metadata it stores from GitLab gains the fields the newer client reads:
- a project carries `duo_sast_fp_detection_enabled`, `duo_sast_vr_workflow_enabled`, `duo_secret_detection_fp_enabled` and `only_allow_merge_if_all_status_checks_passed`;
- a project's owner carries `commit_email`, `discord`, `github`, `local_time`, `preferred_language`, `pronouns` and `work_information`.

Nothing is removed or renamed. Issues, notes, labels, milestones and releases keep the same fields.

The AWS, Google Cloud and Azure SDKs, gRPC, `golang.org/x/oauth2`, `x/sync`, `x/sys` and `x/text` move to their latest minor and patch releases.

The release workflow's actions move to their latest minor and patch releases. The release is still signed with cosign 2.6.5, with the same signature files, so the verify commands in the README still apply.

Nothing else changes in how gitdr runs. The manifest stays `gitdr.manifest/v5`, and `--output json` is unchanged.
