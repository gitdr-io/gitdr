## Before you upgrade

A source now follows a redirect only to the scheme and host of its base URL. A redirect anywhere else, another host, port or scheme, fails the request before anything is sent there, and the error names the two hosts and nothing more:

    refusing a redirect from https://ghes.example.com to https://elsewhere.example.com: it leaves the API

github.com and gitlab.com do not redirect the calls gitdr makes, so this matters for GitHub Enterprise Server and self-managed GitLab behind a proxy. A base URL of plain http whose server redirects to https now fails too; set the https URL.

## Security

gitdr is now built with Go 1.26.10, which fixes GO-2026-6809 in `crypto/x509`. Certificate verification now distrusts intermediate certificates that are known to be compromised. Every HTTPS connection gitdr opens, to a source or to a destination, goes through this check, so the fix applies to every run. v0.1.23 and earlier were built with Go 1.26.9.

`golang.org/x/net` moves to v0.62.0, which fixes GO-2026-6860 and GO-2026-6866 in its HTML parser. gitdr never parses HTML, and govulncheck finds no call to either one. It is updated anyway, so a scanner that reads the module list inside the binary has nothing to flag.

A source's token now goes only to its API. Up to v0.1.23, with a GitHub App or a GitLab token, a redirect to another host carried the token there, and a redirect from https to http carried it in the clear. The answer from that host was also read as the API's, clone URLs included, so git would then have sent the token to whichever host those named. A GitHub token file was already held to its host and to https.

## Dependencies

go-github moves to v93, the GitLab client to v3 and the Azure storage management SDK to v4. gitdr's own code changes only its imports, and three things follow from the libraries:
- The metadata gitdr stores gains fields the old versions dropped. On GitHub, issue comments carry `minimized`, `performed_via_github_app` and `pin`, and review comments carry `body_html`, `body_text` and `_links`. On GitLab, a project carries `automatic_rebase_enabled` and `merge_train_enforcement`. Nothing is removed or renamed.
- A GitHub response with bytes after its JSON is now an error instead of being ignored.
- The Azure WORM check reads the immutability policy from Resource Manager with api-version 2026-09-01 instead of 2024-01-01. A policy it cannot read as locked is still unknown, never immutable.

The AWS, Google Cloud and Azure SDKs, `golang.org/x/crypto`, `x/net` and `x/text` move to their latest minor and patch releases.

The release workflow's actions move to their latest minor and patch releases. The release is still signed with cosign 2.6.5, with the same signature files, so the verify commands in the README still apply.

Nothing else changes in how gitdr runs. The manifest stays `gitdr.manifest/v5`, and `--output json` is unchanged.
