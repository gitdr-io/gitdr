## Before you upgrade

git and git-lfs no longer get gitdr's whole environment. From it they get `PATH`, `HOME`, `TMPDIR`, the proxy variables (`HTTPS_PROXY`, `HTTP_PROXY`, `ALL_PROXY` and `NO_PROXY`, in either case), the CA variables (`SSL_CERT_FILE`, `SSL_CERT_DIR`, `GIT_SSL_CAINFO` and `GIT_SSL_CAPATH`), and `GIT_HTTP_LOW_SPEED_LIMIT` and `GIT_HTTP_LOW_SPEED_TIME`. A secret in gitdr's environment never reaches them. Any other variable that changed what git does, `GIT_CONFIG_GLOBAL`, `GIT_SSL_NO_VERIFY` or `XDG_CONFIG_HOME` for instance, now has no effect, and gitdr logs a warning as it starts that names each one it found. Put that configuration in `/etc/gitconfig`. git's messages are in English whatever the locale.

The image installs `/usr/bin/gitdr` owned by root with mode 0711. The user it runs as can run it and cannot read it, so the kernel starts it non-dumpable, and git, which runs as the same user, cannot read gitdr's environment or memory. If you install the binary yourself, do the same:

    sudo install -m 0711 -o root -g root gitdr /usr/local/bin/gitdr

gitdr takes its own secrets out of its environment once it has read them, so an AWS `credential_process` or the Azure CLI, which the cloud SDKs start, no longer sees `GITDR_MANIFEST_SIGNING_KEY` and the rest.

The systemd unit and the cron wrapper in `deploy/` changed. Only root reads `/etc/gitdr/gitdr.env` now, `/etc/gitdr` and `config.yaml` belong to root, and every run gets an empty `HOME` of its own. The cron entry runs the wrapper as root, which drops to the gitdr user. On a VM installed from the old samples:

    sudo chown root:root /etc/gitdr/gitdr.env && sudo chmod 0600 /etc/gitdr/gitdr.env
    sudo chown root:gitdr /etc/gitdr /etc/gitdr/config.yaml

then copy the new `gitdr.service`, or the new wrapper and cron entry, as `deploy/README.md` shows. On cron do both together: the old wrapper reads `gitdr.env` as the gitdr user and fails once root owns it.
