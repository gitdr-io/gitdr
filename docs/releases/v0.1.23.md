## Before you upgrade

A copy's recorded refs now come from the mirror the bundle was made from, and are checked against the bundle. A repository whose clone or bundle does not hold what the source advertised now fails by name and stores nothing. In v0.1.22 such a repository could be reported as a success with a bundle missing branches. The two new failures read:

    the clone lacks <ref>, which the source advertised before the clone and still advertises
    the bundle written from the clone does not declare the refs the clone holds

A repository whose HEAD names a branch that does not exist, after a default branch was renamed or deleted, is now copied whole: every branch and tag, with no HEAD in the bundle. A restore brings back every ref and checks nothing out, and a drill compares HEAD only when the copy recorded one.

Every successful repository entry now carries `refs` and `copiedAt`, including when the listing before the clone failed. The manifest stays `gitdr.manifest/v5`.

## New

`gitdr backup --recopy <list>` copies the named repositories even when they are unchanged, for example after a copy failed its read-back. The list is comma-separated, the flag can be given more than once, and `backup.recopy` or `GITDR_BACKUP_RECOPY` set it too. A copy that already exists for the run's date stays as it is, because writes are create-only. A name the source does not list gets a warning, and the run goes on.

## Verify

`gitdr verify` reads artifacts concurrently, within the existing concurrency setting, and its output is unchanged. Against a store that takes 250 ms per read it is about four times faster. A verify that is stopped part way now names every artifact it did not read, instead of counting it as read.

## LFS

An LFS fetch that outlives its GitHub token runs again with a fresh one, for as long as it makes progress. git-lfs writes its environment, token included, to a log when a fetch fails, and those logs are now left out of the stored LFS archive.

## Azure

An Azure upload commits only a stream of exactly the artifact's size. Up to v0.1.22 a stream that ended early or ran long was committed as it was.

## Dependencies

The AWS, Google Cloud and Azure SDKs and OpenTelemetry move to their latest minor and patch releases. The release is signed with cosign 2.6.5. The signature files and their format are unchanged, so the verify commands in the README still apply.
