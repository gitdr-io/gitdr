## Before you upgrade

On Azure, gitdr now says a container is immutable only when its retention policy is locked, and only Azure Resource Manager can see the lock. Set `destination.azure.subscriptionID` and `resourceGroup` so it can look.

- With `worm.require` or `--require-worm` set and neither of those, every Azure run refuses to write after the upgrade.
- If gitdr reaches Azure with an account key, SAS or connection string, it can't report `immutable` until it also has an Entra identity through DefaultAzureCredential and network access to management.azure.com.
- Setting only one of `subscriptionID` and `resourceGroup`, or either without `account`, stops gitdr at startup.
- It goes the other way too. A container under a locked container-level policy used to read `not-immutable`, and with both settings it now reads `immutable`.

## New

`gitdr drill -no-report` re-runs the restore proof with read access and the public key, and writes nothing.

    gitdr drill --config config.yaml --manifest <manifest-key> --no-report

`drill --output json` now says where the signed report went, in `reportKey`.
