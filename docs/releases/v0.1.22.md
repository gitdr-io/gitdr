## Security

gitdr is now built with Go 1.26.9. It fixes twelve vulnerabilities in the standard library that govulncheck found reachable from gitdr's code: seven in net/http, most of them in HTTP/2, two in html/template, and one each in crypto/tls, net/textproto and os. The one in os affects Windows only. golang.org/x/net moves to v0.60.0, which carries the same HTTP/2 fixes for the libraries that use its copy.

Configuration and output are unchanged, so upgrading is only a version bump.

The README has a new section, Verifying a release. Its cosign commands name the release workflow and the tag, so a certificate issued to any other workflow in the repository fails the check.

## Writes commit only the artifact

A write now becomes an object only when the stream holds exactly the artifact's size. Writes are create-only, so in a locked bucket a wrong object stayed for the bucket's whole period, at a key no copy could be written to again that day.

- `gcs`: up to v0.1.21 the size was ignored, and a read that failed part way was followed by a close that committed what had been read. A short, long or failing stream now abandons the upload, and nothing is stored at the key.
- `s3`: up to v0.1.21 a stream that ran past the artifact's size could be stored as its first bytes and reported written, because Content-Length and the CRC32 gitdr computed both covered those same bytes. That held for uploads in parts on every store, and for a single PUT over TLS. The last bytes of a body are now sent only once the stream is seen to end there, and the end of a stream is read again just before an upload in parts is completed. A stream that is anything other than the artifact is refused before anything is committed.

## Google Cloud Storage through the S3 API

SPEC now records what Google's S3 interoperability API does with Object Lock, measured on real buckets with the aws CLI and an HMAC key. gitdr already behaved this way, and new tests pin it.

- On a bucket with Object Retention Lock, the lock check reads `immutable`. Each object gets gitdr's COMPLIANCE retention, which Google stores as Locked, and gitdr reads it back.
- On a bucket protected only by a Bucket Lock retention policy, the check reads `unknown`, because that API cannot see Bucket Lock. `--require-worm` refuses such a bucket. The `gcs` destination type reads the policy, so use it there.
- Google refuses lock headers on a bucket without Object Retention Lock, so gitdr never writes an unlocked object while believing it locked.
